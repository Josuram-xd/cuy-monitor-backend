# Contract — Events (ingestion)

> Source of truth for every producer (`cuy-monitor-ai-service`, `cuy-monitor-arduino`) and for the consumers of the stored events (`cuy-monitor-db`, `cuy-monitor-dashboard`).
> Other repos copy from here; they never redefine it. Current `schemaVersion`: **1**.

All producers send the **same envelope** to the **same endpoint**. The backend picks what to do from `type`.

```http
POST /api/v1/ingestion/events
X-API-Key: <API_KEY>
Content-Type: application/json
```

Ingestion does **not** use JWT: producers are not users.

---

## 1. Envelope

```json
{
  "eventId": "3f1c2a5e-8f0b-4a53-9d0e-6b1c0a7e9a11",
  "type": "BEHAVIOR",
  "cageId": "cage-1",
  "timestamp": "2026-10-05T14:32:00Z",
  "source": "ai-service",
  "schemaVersion": 1,
  "payload": {}
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `eventId` | string (UUID) | yes | Generated by the **producer**. Idempotency key: a retried event keeps the same `eventId`. |
| `type` | string | yes | One of `BEHAVIOR`, `AUDIO`, `WEIGHT`. Selects the payload shape and the adapter. |
| `cageId` | string | yes | The cage's public **code** (`"cage-1"`), not its numeric primary key. |
| `timestamp` | string (ISO-8601 UTC) | yes | When the event **happened** (end of the window for `BEHAVIOR`), not when it was sent. Always UTC, with `Z`. |
| `source` | string | yes | Who sent it: `ai-service` or `arduino`. |
| `schemaVersion` | integer | yes | `1` for this document. Bumped only for breaking changes (section 6). |
| `payload` | object | yes | Shape depends on `type` (section 2). |

Unknown extra fields in the envelope or in a payload are ignored.

### Which producer sends what

| `type` | Producer | `source` | Goes through | Scope |
|---|---|---|---|---|
| `BEHAVIOR` | `ai-service` | `ai-service` | internal Docker network (`http://backend:8080`) | one guinea pig |
| `AUDIO` | `ai-service` | `ai-service` | internal Docker network | whole cage |
| `WEIGHT` | `serial_bridge` (arduino repo) | `arduino` | HTTPS through Caddy (`https://cuymonitor.duckdns.org`) | whole cage |

`AUDIO` and `WEIGHT` are cage-level: they carry no guinea pig and are stored with `guinea_pig_id = NULL`.

## 2. Payloads

### 2.1 `BEHAVIOR`

One event **per guinea pig per 60 s window**.

```json
{
  "color": "RED",
  "windowSeconds": 60,
  "stillSeconds": 48,
  "feederVisits": 0,
  "watererVisits": 1,
  "avgGroupDistance": 0.72,
  "probAnomaly": 0.81,
  "detectionConfidence": 0.93
}
```

| Field | Type | Rules |
|---|---|---|
| `color` | `MarkColor` | Color of the mark on the guinea pig's back. The backend maps `(cageId, color)` to a registered guinea pig. Never guessed: if the color is unclear, lower `detectionConfidence` instead. |
| `windowSeconds` | integer | Length of the window. `60` today. |
| `stillSeconds` | number | Seconds the guinea pig was still inside the window. `0 ≤ stillSeconds ≤ windowSeconds`. |
| `feederVisits` | integer | Visits to the feeder (`feeder`) in the window. `≥ 0`. |
| `watererVisits` | integer | Visits to the waterer (`waterer`) in the window. `≥ 0`. |
| `avgGroupDistance` | number | Average distance to the rest of the group, normalized to the image diagonal. `0–1`. |
| `probAnomaly` | number | Classifier probability that the window is anomalous. `0–1`. |
| `detectionConfidence` | number | Confidence of the color/detection for this window. `0–1`. Low values are dropped by the backend's `ValidationHandler`. |

### 2.2 `AUDIO`

One event per classified audio clip of the cage.

```json
{ "label": "DISTRESS", "probability": 0.88, "durationMs": 960 }
```

| Field | Type | Rules |
|---|---|---|
| `label` | string | `DISTRESS` or `NORMAL`. |
| `probability` | number | Probability of `label`. `0–1`. |
| `durationMs` | integer | Length of the analyzed clip in milliseconds. `> 0`. |

### 2.3 `WEIGHT`

One reading of the cage scale (about one every 10 s).

```json
{ "grams": 812.4, "stable": true }
```

| Field | Type | Rules |
|---|---|---|
| `grams` | number | Weight on the platform in grams. `≥ 0`. |
| `stable` | boolean | `true` when the scale value settled. Only stable readings feed the weight trend. |

The weight is **not** tied to a specific guinea pig in this version.

## 3. Shared enums

Values are `UPPER_SNAKE_CASE` strings, identical in JSON, Java and PostgreSQL (`VARCHAR + CHECK`).

| Enum | Values | Used in |
|---|---|---|
| `EventType` | `BEHAVIOR`, `AUDIO`, `WEIGHT` | envelope `type` |
| `MarkColor` | `RED`, `BLUE`, `GREEN`, `YELLOW`, `ORANGE`, `PURPLE`, `BLACK`, `WHITE` | `BEHAVIOR.color`; guinea pig registration |
| `GuineaPigBreed` | `AMERICAN`, `PERUVIAN`, `ABYSSINIAN`, `TEDDY`, `SILKIE`, `SKINNY`, `CRESTED`, `OTHER` | guinea pig registration (not sent by producers) |
| `CoatColor` | `WHITE`, `BLACK`, `BROWN`, `CREAM`, `GRAY`, `CINNAMON`, `BICOLOR`, `TRICOLOR` | guinea pig registration (not sent by producers) |
| `HealthStatus` | `NORMAL`, `OBSERVED`, `ALERT`, `CRITICAL` | REST API and WebSocket (not sent by producers) |
| `AlertStatus` | `OPEN`, `REVIEWED` | REST API and WebSocket (not sent by producers) |
| `UserStatus` | `PENDING_VERIFICATION`, `ACTIVE`, `DISABLED` | auth API |

Producers only ever send `EventType` and `MarkColor`. The others are listed here because they are shared across repos: a change to any enum follows section 6.

## 4. Responses

| Status | Body | Meaning | Producer action |
|---|---|---|---|
| `202 Accepted` | `{ "eventId": "...", "status": "ACCEPTED" }` | The event went through the pipeline. | Done. |
| `400 Bad Request` | `{ "error": "<code>", "message": "..." }` | Envelope invalid: missing field, unknown `type`, malformed JSON. | **Do not retry**; fix the producer. |
| `401 Unauthorized` | `{ "error": "<code>", "message": "..." }` | Missing or wrong `X-API-Key`. | **Do not retry**; fix the key. |
| `5xx` / network error | — | Backend or network problem. | **Retry with backoff**, keeping the same `eventId`, with a small bounded buffer. |

Errors follow the API convention `{ "error": "<code>", "message": "..." }`.

---

## 5. Idempotency and ordering

- `eventId` is the primary key of the stored event. Sending the same `eventId` twice never creates two events.
- Events are processed synchronously inside the HTTP request; the `202` means the pipeline finished.
- Events may arrive out of order after retries. The backend uses `timestamp`, not arrival time, to place an event in a window.

---

## 6. Versioning and changing this contract

- Adding an **optional** field, or a new value to an enum the producers don't send, is compatible: keep `schemaVersion`.
- Renaming or removing a field, changing a type or unit, or adding a required field is **breaking**: bump `schemaVersion` and keep the backend accepting the previous version while producers migrate.
- Any change here must be done **first** in this file, then announced to the other repos: `cuy-monitor-db`, `cuy-monitor-ai-service`, `cuy-monitor-dashboard`, `cuy-monitor-arduino`.

See also: `examples/` (one JSON per event type, Task 3.4) and `rest-api.md` (Task 3.3).
